## 使用

1. 在 Android Studio 打开此目录，运行 `app`，或安装 `app/build/outputs/apk/debug/app-debug.apk`。
2. 在「计划」导入 GPT 生成的 PDF，点击「阅读原文」查看，或点击「提取打卡项」勾选建议。
3. 提取项默认每天重复；点击打卡项可编辑内容、分类和重复星期。删除模板不影响历史记录。
4. 在「今日」选择日期，完成计划打卡，记录饮食、训练和身体指标。点击记录可编辑或删除。一天保留一组身体指标。
5. 在「趋势」切换 7 / 30 / 90 天 / 1 年，以及体重、体脂、腰围。曲线按真实日期绘制，缺失记录不填零。
6. 在「设置」查看本地文件占用、进程 PSS 内存和累计 CPU 时间，并清理所选日期范围内的记录。

## PDF 能力与限制

- 导入时复制原始文件到应用私有目录，之后不依赖原文件路径。最大 30 MB。
- 原文逐页渲染，单页位图限制在 1600 × 2200 内，切页释放旧位图。
- 使用 Android 系统 [PdfRenderer.Page.getTextContents](https://developer.android.com/reference/android/graphics/pdf/PdfRenderer.Page#getTextContents()) 在本地提取文本，再以中英文关键词提出建议。每次最多读取 100 页 / 约 50 万字符，最多提供 60 个候选。
- 这是规则提取，不会自动理解复杂表格、训练周期、周次安排或营养含义；必须核对原文再勾选。扫描件不支持 OCR。可手动添加打卡项。
- 热量由用户填写，不根据食物描述自动估算。体重、体脂、腰围均为手动录入，不连接秤或手环。

## 本地存储与清理规则

- SQLite：`databases/fitness.db`；PDF：`files/plans/`，均位于应用私有目录。
- 关闭 Android 自动备份，未申请联网权限。本版没有导出或云同步，卸载或系统清除应用数据会丢失记录和导入副本。
- 可清理近 1 / 3 / 7 天、1 / 3 / 6 个月、1 年及全部记录。近 N 天含今天，例如近 3 天是今天和之前两天。月、年按本地日历计算：今天减相应月 / 年再加一天，首尾包含。
- 清理以记录所属日期为准，清理饮食、训练、身体指标和打卡完成记录；保留计划模板和 PDF。清理前显示日期范围及数量并确认，之后执行 SQLite VACUUM 回收数据库空间。PDF 和模板可在「计划」单独删除。
- 文件占用统计与进程运行内存分开显示。PSS 是当前快照，CPU 是当前进程累计 CPU 时间；不能据此推算完整耗电量。耗电可从 Android 系统应用设置查看。

### 1.0.1 启动修复与真机验证

后续连接手机后，崩溃日志定位到 `FitnessDb.onConfigure`：`PRAGMA secure_delete=ON` 会返回结果行，使用 `execSQL` 执行会抛出 `SQLiteException: Queries can be performed using SQLiteDatabase query or rawQuery methods only`，导致首页首次读数据库时崩溃。现改为 `rawQuery` 并读取结果触发执行，保留原有安全删除设置，不更改表结构或清除用户数据。

修复版 versionCode 2 / versionName 1.0.1 已通过编译、5 项逻辑单元测试、Lint 和连接手机上的 2 项回归测试：`LocalDataTest`（隔离数据库持久化、配置和清理）及 `StartupTest`（实际启动、四页切换）。设备测试不写入或清理用户的正式记录。
